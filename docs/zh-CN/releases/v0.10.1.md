# v0.10.1：加强执行安全，明确证据关联

[English](../../releases/v0.10.1.md) | 中文

发行说明草稿，本版本尚未发布。

v0.10.1 重点改进 daemon 访问控制、采集兼容性、关联准确性和 TLS 采集稳定性。
Dashboard 保留现有布局和调查入口。

## 升级前先看

请先阅读[升级指南](../upgrading-v0.10.1.md)。以下默认行为有变化：

- daemon 默认要求 Bearer Token，复用本地令牌文件，并检查浏览器请求。带请求体的写入使用 JSON。
- HTTP 采集默认限时 60 秒，限制工作目录和子进程环境，Shell 命令需显式允许。
  本地 `launch`、`record` 保留终端交互和长任务支持。
- 证据包导入通过 `--pub-key` 验签后才写入。历史无签名包需要显式使用 `--allow-unverified`。
- Docker 兼容命令移除 capability，默认采用调用方的有效 UID:GID，也可在任务中指定账号。

升级前备份数据目录。已有签名 Demo 及其公钥仍可使用。

## 关联与调查

意图覆盖现在按具体工具调用判断。一次调用有意图记录时，其他调用缺失的上下文仍会单独显示。
委派分析保留有歧义的候选消息，显式调用绑定和持续策略分别按各自作用域处理。

外传证据拆成三个问题：正文命中了什么内容、哪些读取可能提供内容、记录属于哪次执行。
关联使用精确路径、可用的内容版本、观测时间和显式身份。
详情中保留这些判断及来源引用，签名包和选择性回放沿用相同状态。

## TLS 采集

截断、丢块和协议状态缺损以不完整片段保存。HTTP/1.1 重组和 HTTP/2 HPACK 解码停止使用
已受损的状态，原始片段仍可查看，不再从残缺字节生成模型决策或请求响应配对。

原生采集记录调用序号和块偏移，合并同次调用的连续片段。
进程和库加载线索触发有界的定向 TLS 发现，后续短命进程可复用已挂载的库目标。
需要覆盖最早调用时，仍可提前配置明确的库目标。

普通单次调用的采集上限保持 4 KiB。现有正文阅读器分别展示消息完整性、片段原因和采集位置，
与正文分页区分；离线回放也保留这些信息。

## 兼容性修复

本地终端输入和 Ctrl-C 保留前台进程组语义；有时限的 daemon 任务继续清理超时进程及其子进程。
独立 CLI 命令树各自使用对应的数据目录和语言设置。

制品导出接受合法名称，同时保留目标路径检查和受限文件权限。
签名导入脚本及 daemon 示例已按当前验签、鉴权默认值更新。
表字段与 JSON 对象中的带引号命令使用一致的脱敏结果，签名导出再导入后，采集清单仍保持一致。

## Linux x86_64 验收

x86 探针读取命名 tracepoint 的系统调用号时，不再把对齐填充算入调用号。
生成参数补上 BPF ISA v3，满足 TLS 原子计数器要求。
系统调用与 TLS、guest 常驻服务、K3s 归属、Pod 重建和故障恢复已在 Ubuntu 6.8 上通过。
[验收报告](../../benchmarks/v0.10.1-x86/README.zh-CN.md)记录了实际源码、证据及尚需处理的 WSL/KVM/CET 环境限制。
