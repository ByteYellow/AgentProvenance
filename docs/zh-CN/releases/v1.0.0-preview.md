# v1.0 源码预览：跨执行环境的证据关联

[English](../../releases/v1.0.0-preview.md) | 中文

本文介绍 `feature/v1.0-portable-evidence` 分支的现有能力，已发布版本仍为 v0.10.1。
原有的执行记录、图谱调查和签名证据工作流继续保留。

## 为什么扩展这条证据链

本地进程树可以解释同一环境内的执行。当 Agent 将命令交给另一沙箱，
或反复使用浏览器、Notebook kernel 时，调查需要补充三类上下文：

- **跨环境**：将来源 Tool Call 与目标执行作用域、结果连接起来，并保留重试与证据交付过程。
- **长驻应用内部**：记录浏览器操作和 Jupyter 请求身份，逐项查看动作与输出。
- **恢复与分享之后**：保留实例代次、采集条件和回执，让恢复后的任务与导出的证据继续保有来历。

这些能力沿用现有的 Run、图谱和 Bundle 工作流。
先阅读[沙箱部署说明](../deployment-modes.md#先看-agent-和工具在哪里运行)，
再按自己的环境选择执行入口和采集器。

## 追踪远端工具调用

Agent 可以在一台机器上运行，将独立命令交给另一处 Linux 沙箱执行。
可选的 Claude 命令路由保留原生会话与工具调用身份，连接派发记录、每次执行尝试、
远端作用域、保存的结果和签名交付回执。

传输重发复用原执行尝试，显式重新执行则创建新尝试。
执行、采集、交付分别记录状态：命令已经结束时，采集仍可能存在缺口，回执也可能尚未收到。
执行器重启后可以恢复查询和停止仍存活的原作用域，避免重新运行命令。

[执行交接指南](../execution-handoff.md)说明可信入口、鉴权、配置、独立命令边界，
以及如何双向查询已保存的调用与执行关系。

## 让文件操作与命令使用同一工作区

可选的[受控远端工作区](../workspace.md)让整个 Harness 在权威文件所在的机器运行。
Read、Edit、Write、Bash 共享工作区身份和版本。编辑使用作出修改决定时读取的版本
或摘要；发生冲突时要求重新读取。Bash 将执行前后的文件清单与现有快照、执行结果一起保存。

首期使用 stdio MCP 和本地 JSON CLI，支持 Linux、macOS。文件操作和命令都在
同一工作区完成，无需部署新的公网文件执行服务，也无需同步两份可写副本。

## 记录浏览器与 Notebook

两个可选入口将采集扩展到 Shell 之外：

| 入口 | 保留的上下文 | 可保存的内容 |
| --- | --- | --- |
| Browser | 页面、frame、操作、请求、重定向和 worker 的原生身份 | 文本、下载产物、有限额的截图与敏感字段处理后的 HAR |
| Notebook | kernel 实例、前端会话、请求及父消息身份 | 单元输入、输出、错误和有限额的静态图片附件 |

两个入口均提供可选的 MCP 接口。`basic` 与 `detailed` 都保留原生关系元数据，
正文和附件开关决定具体留存内容。kernel 重启后使用新身份，延迟输出继续引用原请求。

依赖与完整示例见 [Browser 指南](../../browser-context.zh-CN.md)和
[Notebook 指南](../notebook-context.md)。Linux 系统遥测独立采集；
未启用原生 Sensor 时，也可以使用这些应用上下文入口。

Browser 操作现在持久保存接收与结果记录。bridge 重启后，`browser_result` 查询原操作
及其 generation，不重复动作；中断操作保留未知结果。可选的接收方受控导入根据独立
固定的采集摘要核验回执，将核验结论与原始来源声明分别保存。

原生引用同时连接操作、请求生命周期、重定向和文档。接收方可显式配置 Browser context
与已观测进程生命周期的映射，进一步查看该进程的文件、网络证据。派生关系保存规则和
支撑引用；选择性导出按保留的证据重新计算。[Browser 指南](../../browser-context.zh-CN.md)
提供本地图谱、导出配置及 Linux Sensor 验收步骤。

## 把采集条件一起保存

采集清单记录 producer 身份、已知的采集位置、能力观测及变化、接收区间、丢失诊断和
原始批次回执，支持分页 API 与离线查询。未知计数保留为未知值；选择性导出只带走
所选证据能够支持的观测记录。

它回答的是调查中的一个具体问题：任务执行时启用了哪些采集器，哪里报告过缺口？
即使原沙箱已经回收，接收方仍可将这些采集条件与事件一起阅读。

原生 Linux 采集在 Pod 迟到绑定、spool 恢复后保留原接收窗口。
ARM64 使用有界的内核 cgroup 名称缓存，保存短命工作负载的身份线索。
迟到的能力通知保留原时间戳，有效区间按已记录的接收窗口裁剪。

固定版本的 [gVisor SecCheck 入口](../gvisor-seccheck.md)采集 Sentry 事件，
分别保存沙箱身份与生命周期代次。检查点恢复使用外部注册和签名授权区分恢复与克隆实例。
[Firecracker guest 方案](../execution-handoff.md#guest-服务与镜像)提供镜像、内核构建入口及
自动采集、封存服务。amd64 已通过实际启动、签名交付及回执齐全后的回收验收，
见[运行时与性能结果](../../benchmarks/v1.0-amd64/README.zh-CN.md)。

[运行时适配指南](../runtime-adapters.md)提供 native、Guest 和固定 runsc 容器的显式配置。
Guest 绑定保留 Pod、容器及内核启动身份。runsc 当前保存操作回执及容器级 Sentry
采集边界，逐命令 Sentry 关联仍待补齐。新增 Kata/QEMU 组合提供
[固定版本验收流程](../validation/kata-qemu.md)。

## 按范围分享调查

使用 `dashboard export --selection-file` 选择多个 Run，或通过 `--harness`、`--session`
分享一个会话。每份选择分别保留证据边界。导出目录包含保存正文、图谱、搜索和采集观测，
可通过 `file://` 打开，无需原数据库。

CLI 提供三种[交付模式](../derived-evidence.md)：未签名的阅读副本、由导出者签名的
选定内容，以及保留生产者签名的完整原件。完整原件模式要求选择完整 Run、明确指定
已登记的 Bundle，并确认交付其全部内容。选择性或脱敏交付不会附带被排除的原件。

接收方使用独立的 `agentprov-verify` 命令和自己配置的外部密钥、角色策略进行验证。
文件完整性、原始签名、导出签名、信任和采集覆盖分别报告。对应 Dashboard 控件暂时
保留在本地预览。Browser／Notebook 附件采用静态阅读方式；阅读器不会执行保存的命令，
也不会自动加载证据中的远端资源。
