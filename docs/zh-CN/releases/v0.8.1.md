# AgentProvenance v0.8.1

[English](../../releases/v0.8.1.md) | 中文

v0.8.1 增加以 Jev 为例的外部评估器接入示例。代码位于 `demo/jev-judge/`，独立于核心采集和查询路径，演示如何使用已有证据与信号接口。

## 新增内容

- 直接调用 TypeSafe API 的示例，包含三类带类型约束的判断：声明的行动、运行时行为是否符合授权，以及是否存在未授权传输秘密的证据。
- 单独启动的演示工作台，展示原始证据和模型回答、问题与标准的差异、比较指标，以及人工评审日志。
- 人工编写的基线和候选评估标准，针对相同案例状态执行评估。两个版本使用相同、固定的覆盖检查规则。
- 明确的候选版本批准／拒绝操作，以及通过现有 AgentProvenance 接口导出已评审的 `quality_signal`。参考评审修改后，原批准失效；不会安装策略或自动提升候选版本。

核心负责证据、关联、校验和信号摄入；示例负责自身的 Jev 调用、评估标准和评审流程。它不增加主 CLI 命令、后台 worker、主 Dashboard 导航，也不要求用户必须配置模型服务。

从 [Jev 示例](../../../demo/jev-judge/README.zh-CN.md)开始。流程先校验已有的带签名多 Agent 证据包，在明确授权后执行 12 次 API 调用，将研究数据保存到本地私有目录。再次打开已有研究无需密钥，也不会追加模型调用。

## 验证与限制

2026-09-22，12 次实际调用均返回 `jev-1.13.0`。拒绝案例中，原始传输判断从 v1 的 `not_observed` 变为 v2 的 `unknown`，其他案例分类不变。经过确定性的覆盖缺失检查后，两个版本都为 `unknown`。这组指定案例的比较不是独立留出测试、模型训练结果，也不能证明普遍安全性。

源证据包通过签名与图校验。本地浏览器验收在独立副本上检查评审、批准、信号下载、导入、读取和图校验。测试评审记录明确标注为自动化记录；主研究数据仍等待真实人工评审。无密钥测试覆盖客户端和评审边界；CI 不向服务商发送证据。

评审人姓名由填写者自行提供。本地哈希可相对于已保存清单发现意外变更，但不能抵御拥有目录权限的人整体重写或回滚文件。源证据签名不覆盖后续判断和批准。该工作台是仅绑定本机回环地址的示例，不是带身份认证的多用户审批服务。

## 兼容性

本版本未改动核心 Go 包、数据库迁移、原始示例证据包或既有 Dashboard 路由。Jev 页面与只读证据 Dashboard 分开。只有这个可选示例需要在 macOS/Linux 上安装 Python 3.9 及以上版本；Windows 用户可在 WSL 中运行。已有采集和回放流程不变。
