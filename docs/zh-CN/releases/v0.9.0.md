# v0.9.0：保存 Agent 执行上下文

[English](../../releases/v0.9.0.md) | 中文

**状态：尚未发布。** 以下能力位于开发中的源码版本；当前已发布下载仍为 v0.8.2。

AgentProvenance 在运行时证据之外，进一步保存执行前后的对话和上下文：用户要求了什么、
运行框架调用了哪些工具、工具返回什么，以及来源实际记录的权限和配置。
即使原 Agent 和工作区已不在，这些记录仍可检查。

## 查看真实执行

构建当前源码，打开 DeepSeek 开发任务的签名记录：

```sh
go build -o agentprov ./cmd/agentprov
./agentprov demo deepseek-context
```

Agent 为一个 Python 报表增加按日汇总，并运行七项测试。打开 **Agent 会话**，查看任务、
工具输入结果和配置；使用**打开已保存内容**阅读完整工具输出。
也可以直接从图中选择变化的文件，查看最终保存的文本，不必展开会话。
已有证据关联的工具记录支持在图谱与会话之间双向定位。

回放先校验原始签名，再导入独立的临时存储。无需联网或模型凭据，也不会重新执行
Agent 的命令。[采集详情与限制](../../../demo/deepseek-context/README.zh-CN.md)。

## 采集和查询

在受支持的 Agent 已安装并完成认证后：

```sh
./agentprov launch --file-diff -- dsh headless --json 'Inspect the project and run its tests.'
./agentprov launch --context-dir /path/to/sessions -- codex
./agentprov context coverage --run RUN_ID
./agentprov context list --run RUN_ID --kind configuration --revisions
```

Claude Code 与 Codex 提供共同的消息、工具结果和来源配置适配。
DeepSeek Harness 0.1.7-rc.2 使用原生 `session.v4.jsonl.zstd`，继续读取支持的 v3 会话。
已有 Kimi/Grok 格式保持兼容，但不表示重新复现其历史云端行为。

来源发现和解析在执行退出后进行，支持显式指定目录、文件或会话 ID。恢复会话时核验
此前保存的来源前缀，历史记录不作为新活动。子会话使用来源记录的真实身份。
多个并发候选、来源身份变化或不支持的格式会给出诊断，不靠猜测补齐关联。

配置比较保留任务、模型、工作目录、审批与沙箱字段的变化；来源包含 MCP、skills、plugins
信息时一并保存。来源没有提供的信息保持未知。权限请求、审批策略配置与实际批准是不同记录。

CLI 与 [HTTP API](../../agent-context-api.yaml) 提供记录分页、正文读取、配置比较、覆盖情况和已记录的关联。
查询证据不会拿当前工作区文件替代历史内容。[上下文使用指南](../agent-context.md)。

## 正文移植与覆盖

较长正文先脱敏、再计算哈希，按有界分段保存并随自包含证据包导出。
工具结果、原始来源记录和较长对等消息都可分页读取。每份正文最多保存 32 MiB，
无需提高原有的 4 MiB 单对象证据包内嵌上限。

一次启动的 Hook 日志与选中会话共用 256 MiB 解压后输入预算和 25,000 条归一化记录预算，
最多选择 128 个会话来源。超限显示部分覆盖。变化文件的最终文本由用户选择启用，
另有独立预算，表示采集时的最终状态，不是每次文件写入的完整历史。

上下文报告区分禁用、未发现、正常空记录、成功、部分成功、失败、归属不明和历史未记录。
运行时报告保留各自的统计范围与限制。签名和哈希有效不等于采集完整；
节点累计丢失数量不会被编造成本次执行的丢失数量。

已知探针/TLS 覆盖限制与未确定的完整性问题分开展示。新的原生采集保留启动 ID/PID/
出生时间身份、内核时间戳、子进程出生 cgroup 和有界关闭排空。这些改进生命周期归属，
不把启发式工具调用关联变成确定的模型因果证明。

## 兼容性与范围

- 已有存储升级到数据库版本 19，新字段未记录时仍为空。升级前按常规备份数据目录；
  不支持用旧版二进制直接降级已升级的数据库。
- 六份历史签名 demo 的证据包、签名和公钥不变，保留当时的原始证据及能力边界。
- 新导出保存遥测批次成员，使既有批次完整性校验继续可用；不重建历史缺失的成员信息。
- 已有图视图、风险信号、进程树、网络与数据外发面板继续可用；中英文展示不改写来源原文。
- 新的真实采集使用 ARM64 Linux VM。保留既有平台支持，不把该案例视为新的 x86 或 microVM 验收。
- ARM64 Linux 6.8.0-137 实机回归还覆盖普通 fork、`clone3` 出生 cgroup、迁移、延迟排空
  与持久摄取后的 run 归属；验证 OpenSSL/Python 请求和响应以及 Go TLS 请求采集。
  ARM64 的 Go TLS 响应采集仍不支持。
- 采集不依赖评估器。LLM/Jev 研判仍为可选能力，本版不增加规则自动进化或自动上线。

发布流程保留 Linux/macOS amd64/arm64 的原生压缩包检查。
当前候选版本尚未发布，本地构建与离线回放检查不能代替远端发布任务的实际执行结果。
