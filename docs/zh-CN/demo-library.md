# 按问题选择示例

[English](../demo-library.md) | 中文

先选择要调查的问题，再打开对应记录。下表沿用现有示例名称，将修复前后作为同一故事的不同章节。

## 第一次使用

点页头的**页面导览**，可以逐步了解示例首页或当前执行记录。每一步都可以点「下一步」或「跳过全部」。从对比链接进入时，先看两次运行的差异，关闭对比窗口后再开始导览。

建议从“任务调查与修复”开始。这条路线串起最常用的操作：

1. **了解任务。** 阅读原始指令和工具输出，确认当时要完成什么、结果是什么。
2. **核对证据。** 找到相关文件或外联记录，阅读保存正文，并通过关联事件查看支持依据。
3. **比较变化。** 对照同一组修复前后的 Run，检查配置、文件和网络记录。采集范围不同的项目会保留不确定状态。
4. **交付结果。** 选择需要分享的 Run 或会话，在导出预览中核对内容，再下载离线阅读副本。

只想看某项结果时，可以直接使用下表的入口。图谱用于继续追踪关系，原始记录用于核对细节。

| 现在要做什么 | 使用哪个入口 | 会得到什么 |
| --- | --- | --- |
| 查看 Agent 说了什么、调用了什么 | 任务与对话、工具调用 | 原始指令、输入、输出和对应时间 |
| 找一条报错、域名或文件名 | 搜索 | 保存内容中的命中片段、全文和证据跳转 |
| 判断两次运行哪里不同 | 比较 | 配置、文件、网络等维度的对照与采集范围 |
| 追查文件或网络活动来自哪里 | 关联图谱 | 支撑事件、关系依据和适用范围 |
| 检查记录缺了什么 | 采集情况 | 已保存内容、主动省略、采集缺口及其来源 |
| 让另一位同事查看 | 导出 | 可离线打开的阅读副本；签名交付见[验证指南](derived-evidence.md) |

“执行成功”“采集状态”和“证据验证”分别回答任务结果、记录覆盖和证据校验三个问题。
调查时先看结果及相关原文，涉及缺口或来源争议时再展开对应诊断。

## v1.0 候选示例看什么

示例首页保留四个带图入口：任务调查、远端工作区、Browser／Notebook、多 Agent 协作。
专题和历史调查单独归类。修复案例直接打开对比窗口，A 为检查任务，B 为修复任务。

要看 **Linux x86 实录**，在远端工作区卡片上点「Claude 工作区」或「Kata/QEMU」；
「案例经过」还列有 Kata 首次启动、重建和工作区版本三份记录。Browser／Notebook
卡片上可直接打开「Browser 开启 Sensor」或「中断恢复」。每份实录都有独立阅读器和原始只读 ZIP 下载。

共用阅读器提供以下五条阅读路线，也可通过[本地示例构建](../../previews/v1.0-reader/README.zh-CN.md)查看。
先了解每个案例发生了什么，再沿着对应证据阅读：

| 入口 | 案例经过 | 阅读顺序 |
| --- | --- | --- |
| 任务调查 | DeepSeek 在配置修复前后分别执行调查任务 | 先读任务和工具结果，再通过 Compare 查看两次 Run 的配置及文件变化 |
| 跨环境执行 | 两个 Claude 会话产生三个远端执行尝试，并演练回执响应丢失后的恢复 | 选中来源 Tool Call，进入目标 Run 与执行尝试，分别查看执行、采集、交付状态，再返回原调用 |
| 工作区 | 在远端权威工作区完成读取、修改和执行，始终使用同一份工作内容 | 核对输入与输出版本、操作回执，并阅读保存的 `result.txt` 正文 |
| Browser | Agent 通过记录式浏览器入口执行网页任务 | 展开 Agent 会话，进入 Browser／Notebook，查看操作的原生引用、正文、截图及相关请求记录 |
| Notebook | 合成 Jupyter 记录包含图表和一次 kernel 重启 | 查看请求与父消息引用，打开图表，对照重启前后的 kernel 身份 |

前四项使用候选版执行实录。Notebook 展示使用合成样本；此前真实 Claude Notebook
记录保留在[候选验收档案](../benchmarks/v1.0-candidate/README.zh-CN.md)中。
打开页面只读取已保存的观测。当前源码构建已将这些控件接入 Dashboard、静态阅读器和
新导出的离线副本，保留现有图谱布局，补充工作区版本、执行回执，以及 Browser／Notebook
正文和附件阅读。网站下载的阅读副本包含当前阅读器，原始证据下载与下方 `agentprov demo`
入口名称继续保留。

使用 `agentprov demo <入口名称>` 直接打开原记录。两组修复案例会一起载入对应的前后 Run，便于比较。旧 Run ID、签名和证据引用继续指向原来的记录。

10 月和 11 月是报表任务的两次独立复现，查看修复效果时分别在组内比较。
回放链接可以通过 `compare_a=<修复前 Run>&compare_b=<修复后 Run>` 直接打开对比窗口，
两份 Run 都须包含在该回放中。关闭窗口后回到当前记录。

## 记录类型

- **执行实录**：保存某次执行的观测结果。指南列出已记录的采集环境、来源和日期。
- **混合来源**：应用上下文和运行时事件来自不同采集过程。K8s A2A 示例分别标注两者来源。
- **合成样本**：用构造的输入解释关联语义。外发归因示例使用公开标记。
- **评估器接入**：消费已有证据。无密钥 fixture 用于验证接入流程；在线研判需要指南列出的凭据。

## Grok 历史记录

Grok 原场景当前无法复现。两份原记录继续支持签名校验、导入、调查和离线回放。[历史指南](../../demo/grok-codebase-exfil/README.zh-CN.md)分别说明已观察到的模型请求正文、厂商遥测和第三方分析请求。

新版阅读器展示历史记录时，保留原采集日期、证据和签名。重新采集的示例使用新的 Run ID 和独立签名包。

## 分享调查结果

在 Dashboard 的导出预览中选择 Run、会话和保存的记录。生成的只读目录可以脱离原始工作区打开。选择性阅读副本与原始签名证据包分别交付；需要校验签名时，同时保留原包和公钥。

## 加载记录

静态站点先读取轻量目录，再加载所选 Run 的索引和证据。比较两次运行或查看关联会话时，按需读取另一份记录。历史档案在打开前保持未加载状态。

旧回放链接和原始签名包继续保留。阅读器也支持使用单一清单的旧站点，以及自包含的离线导出目录。

在同一台机器上比较两份导出站点，可安装 Playwright 依赖后运行 `node scripts/bench_static_replay.cjs BEFORE_DIRECTORY AFTER_DIRECTORY`。设置 `PLAYWRIGHT_CHANNEL=chrome` 可使用已安装的 Chrome。JSON 报告分别记录冷、热缓存下的传输字节数、图谱可用时间和保留的 JavaScript 堆内存，并附上浏览器、CPU 与源码提交。
