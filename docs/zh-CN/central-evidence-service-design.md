# 中心化证据服务设计

[English](../central-evidence-service-design.md) · 简体中文

**状态：仅有架构设计，当前项目尚未实现此服务。** 下文描述拟采用的规则，不是当前版本的能力承诺。

## 目标

本地和节点级部署将执行上下文与运行时遥测汇入同一张可验证证据图。未来的中心化服务应把这套规则扩展到多个节点，同时保留本地证据格式和校验语义。它不承担任务调度、沙箱平台或通用遥测数据湖的职责。

## 逻辑架构

```text
节点采集端 / 未来的 microVM 采集端
  → 有界本地磁盘缓冲队列
  → 经过认证的批次接收
  → 持久化接收日志
  → 关联与证据物化工作进程
  → 内容寻址对象存储
  → 图与索引存储
  → 查询 / 校验 / 回放 / 取证 API
```

节点采集端负责传感器部署、运行环境身份、本地过滤、队列上限、丢弃计数和实际能力报告。中心服务负责持久接收、跨节点索引、保留策略和共享调查接口。

## 复用的规则

- 保持标准化遥测和应用上下文的数据格式。
- 继续通过 `execution_context_bindings` 表达作用域归属。
- 遥测批次保留来源哈希、事件标识、计数和生产者身份。
- 内容寻址证据对象与签名取证包保持可交换。
- 导入中心服务后，原有本地 `graph verify` 的语义仍然成立。

## 组件职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| 节点采集端 | 采集、过滤、分批、磁盘缓冲、丢弃和覆盖指标 | 全局调度、租户策略 |
| 接收网关 | 认证生产者，校验格式与哈希，返回持久接收凭据 | 图查询 |
| 持久日志 | 缓冲突发流量，保留单个生产者或作用域内的顺序 | 解释证据 |
| 物化工作进程 | 关联、构建图边、派生风险与信号、生成证据对象 | 控制原始传感器 |
| 对象存储 | 保存不可变正文、清单、取证包和回放对象 | 维护可变图索引 |
| 图与索引存储 | 提供有界的谱系和调查查询 | 保留原始大对象 |
| 查询服务 | 时间线、解释、差异、归属、校验、回放、导出 | 执行工作负载 |

## 生产者身份与顺序

每个批次应包含：

- `producer_id`、`producer_profile`、`node_id`。
- 单调递增的 `producer_sequence` 和采集时间范围。
- 事件数、字节数、来源哈希和能力报告。
- 批次封存时的队列和丢弃计数。
- 集群、节点、Pod、容器、虚拟机或本地主机等运行环境身份。

只保证同一生产者序列内部有序。跨节点顺序根据采集时间和时钟质量信息在查询时估计；时钟不一致时，不能将估计结果表述为确定的全局顺序。

## 背压与故障处理

- 生产者同时限制批次数、单批字节数和队列总字节数。
- 网关在持久日志提交后才返回接收确认。
- 使用批次哈希和生产者序号实现幂等重试。
- 队列耗尽时执行配置的 `reject` 或 `drop_oldest` 策略。
- 每次丢弃都计入覆盖证据。没有事件不能被报告为采集完整。
- 查询或物化失败时，节点可继续采集，直到本地队列达到明确的容量上限。

## 安全与信任边界

- 传输使用 mTLS 或等效的工作负载身份认证。
- 授权范围细分到生产者、租户、项目和执行记录。
- 跨信任边界只传输哈希和明确选定的证据正文。
- 主机外锚定与签名使用独立接口，中心存储本身不提供这项保证。
- 中心接收凭据证明服务已持久接收数据，不能证明不可信的生产者采集了所有事件。

## 容量与运行指标

容量按每个生产者每秒的事件数和字节数描述，不能只统计执行记录数量。最低限度应报告：

- 已接收、已过滤、已拒绝、已丢弃的事件数和批次数。
- 队列深度，包括批次数与字节数。
- 接收吞吐量和持久确认延迟。
- 关联覆盖率和传感器环形缓冲区的丢弃数。
- 查询延迟的 p50、p95、p99，以及物化滞后。
- 存储增长量和按保留策略删除的数据量。

## 当前不做的事项

- 实现多租户、计费或集群任务调度。
- 替代 Kafka、对象存储、Kubernetes 或 SIEM。
- 承诺全局恰好一次事件语义。
- 承诺跨主机的确定全序。
- 在当前发行目标中交付中心化服务。

## 开始实现前的条件

先证明节点级运行满足以下条件，再启动中心化实现：

1. 一个传感器观测多个独立工作负载。
2. 过载时遵守队列上限和字节预算。
3. 丢弃与覆盖统计经过导出、导入后仍可查询。
4. 可复现的 10 万事件接收与查询报告。
5. 每个标为 `validated` 的运行环境配置通过证据图语义一致性验收；未来的 microVM 也必须通过相同验收后才能纳入。
