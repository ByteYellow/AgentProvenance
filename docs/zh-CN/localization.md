# 中文适配与正式版验收

正式版应提供完整的中文文档、Dashboard、演示和使用引导。网页中的操作提示、错误、动态摘要和导出说明属于中文适配范围。

工具输出默认使用英文。CLI、传感器、后台服务和脚本的日志、报错、诊断、校验结果不要求逐条翻译，也不作为正式版中文适配的完成条件。已有的可选中文显示保留，后续不再扩充工具输出翻译。命令、参数、结构化输出和原始证据保持原样。

英文是源语言和回退语言。网页优先使用用户的手动选择，并在页面跳转时沿用。首次访问时按浏览器的语言偏好选择中文或英文；没有支持的语言或未提供偏好时，显示英文。命令行在用户未指定语言时使用英文。

## 写作要求

参考[中文技术文档写作规范](https://github.com/ruanyf/document-style-guide)。

- 使用常用词、主动语态和短句。一段只说明一件事。
- 标题按层级组织，不跳级，不在标题末尾加句号。
- 中文使用全角标点，中文与英文、数字之间留半角空格。
- 功能说明直接讲用途、操作和结果。页面标签用短词，必要限制集中说明，避免反复堆叠限定语。
- 同一概念使用同一译法，例如“执行记录”“运行环境”“事件归属”“污点传播”“图视图”。
- 命令、参数、API 字段、规则标识、协议名、路径和原始证据保持原样。界面为这些数据提供中文标签。
- 原始对话、命令输出、签名文件和历史采集数据保留原文，不将译文写回证据。

## 验收原则

语言资源存在不等于页面已经使用。测试应触发对应功能，并检查实际呈现的文字。

英文原文、产品名和机器标识可以保留，但需要说明用途。中文页面应翻译自身的操作提示；其中展示的原始工具日志和诊断可以保留英文。不能把网页自身的提示当成原始证据，也不能通过隐藏功能来减少翻译范围。

只有上表全部通过，并核对正式发布包，才可宣布中文适配完成。阶段提交和预览不代表正式版已具备完整中文支持。
