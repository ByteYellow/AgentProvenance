# v0.9.0: Recorded Agent Context

English | [中文](../zh-CN/releases/v0.9.0.md)

**Status: unreleased.** These capabilities are available in the development
checkout; the current published download remains v0.8.2.

AgentProvenance now preserves the conversation and execution context around its
runtime evidence: what the user requested, which tools the harness called, what
they returned, and which permissions and configuration the source recorded.
The saved records remain inspectable after the original agent and workspace
are gone.

## Inspect a Real Run

Build this checkout and open the signed DeepSeek development-task capture:

```sh
go build -o agentprov ./cmd/agentprov
./agentprov demo deepseek-context
```

The agent adds daily totals to a Python report and runs seven tests. Open
**Agent session** for the task, tool inputs/results and configuration; use
**Open saved content** for full tool output. Select a changed file in the graph
to inspect its saved final text without expanding the conversation.
Recorded links navigate between tool entries and the graph in both directions.

Replay verifies the original signature and imports into a fresh temporary
store. It runs offline, requires no model credentials, and does not rerun the
agent's commands. [Capture details and limits](../../demo/deepseek-context/README.md).

## Capture and Query

With a supported agent installed and authenticated:

```sh
./agentprov launch --file-diff -- dsh headless --json 'Inspect the project and run its tests.'
./agentprov launch --context-dir /path/to/sessions -- codex
./agentprov context coverage --run RUN_ID
./agentprov context list --run RUN_ID --kind configuration --revisions
```

Claude Code and Codex have common message, tool-outcome and source-configuration
adapters. DeepSeek Harness 0.1.7-rc.2 uses native `session.v4.jsonl.zstd`; supported
v3 transcripts remain readable. Existing Kimi/Grok formats remain compatible,
without a claim of reproducing their historical cloud-side behavior.

Discovery and parsing run after execution exits. Explicit directories, source
files and session IDs are supported. Resumes verify the earlier source prefix;
earlier records remain history, not fresh activity. Child sessions use recorded
identities. Concurrent candidates, changed source identity and unsupported
formats produce diagnostics instead of guessed associations.

Configuration comparison preserves changes in task, model, working directory,
approval and sandbox fields, plus MCP/skills/plugins metadata when the source
contains it. Missing information stays unknown. A permission request, configured
approval policy and actual approval are different records.

The CLI and [HTTP API](../agent-context-api.yaml) expose paged entries, saved bodies, configuration
comparison, coverage and recorded links. Querying evidence never substitutes a
current workspace file for historical content. [Context guide](../agent-context.md).

## Portable Content and Coverage

Large bodies are redacted before hashing, stored in bounded chunks, and included
in self-contained forensic bundles. Readers page through saved bytes, including
tool results, raw source records and long peer messages. Body storage supports
up to 32 MiB without raising the historical 4 MiB per-object bundle limit.

Launch shares a 256 MiB decompressed-input and 25,000 normalized-record budget
across its hook log and selected transcripts, with at most 128 transcript sources.
Limits are reported as partial coverage. Final changed-file text is opt-in,
bounded separately, and represents the state at capture, not every file write.

Context reports distinguish disabled, missing, empty, successful, partial,
failed, ambiguous and historically unrecorded sources. Runtime reports retain
their own scope and limitations. A signed graph with valid hashes does not prove
complete capture; node-level drops are not fabricated as per-run loss counts.

## Compatibility and Scope

- Existing stores migrate to schema 19; absent new fields remain absent.
  Make a normal store backup before upgrading. Older binaries are not a
  supported downgrade path for an upgraded store.
- All six historical signed demo bundles, attestations and public keys remain
  unchanged. They retain their original evidence and capability boundaries.
- New exports preserve telemetry batch membership needed for existing batch
  integrity checks. Missing historical membership is not reconstructed.
- Existing graph views, risk signals, process tree, network and outbound-data
  panels remain available. English/Chinese presentation preserves source text.
- The new live capture uses an ARM64 Linux VM. Existing platform support is
  retained; this capture is not new x86 or microVM validation.
- Capture does not require an evaluator. LLM/Jev analysis remains optional,
  with no automatic policy evolution or promotion added in this version.

The release workflows retain native Linux/macOS amd64/arm64 archive checks.
Until this candidate is published, local builds and offline replay checks are
not evidence that those hosted release jobs have run.
