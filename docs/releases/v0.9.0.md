# v0.9.0: Recorded Agent Context

English | [中文](../zh-CN/releases/v0.9.0.md)

AgentProvenance preserves the context behind an agent's execution alongside its
runtime evidence: the original task, conversation, tool inputs and results,
recorded permissions and configuration, and saved file content. These records
remain queryable and portable after the original agent and workspace are gone.

## Highlights

- **Conversation and tool results**: common context adapters preserve messages,
  tool outcomes, source records, resumed sessions and recorded child identities.
- **Configuration history**: compare recorded task, model, workspace, approval
  and sandbox settings, plus MCP, skills and plugins when the source provides them.
- **Portable saved content**: page through long tool outputs and opt-in final
  changed-file text, including after forensic export and offline import.
- **Session-to-graph navigation**: move between a tool entry and its attributed
  runtime evidence through recorded links in the bilingual Dashboard.
- **CLI and HTTP access**: query entries, saved bodies, configuration differences,
  source coverage and graph links through the same evidence model.

## Try the DeepSeek Replay

From an extracted v0.9.0 archive:

```sh
./agentprov demo deepseek-context
```

A real agent adds daily totals to a Python report and runs seven tests. Open
**Agent session** to inspect the task, tool inputs/results and configuration.
Use **Open saved content** for full tool output, or select a changed file in the
graph to read its saved final text.

The CLI verifies the original signature and imports into a fresh temporary store.
Replay is offline, needs no model credentials or Go installation, and displays
the recorded execution without rerunning its commands. The gallery includes
seven signed replays and nine guide entries, including two optional evaluators.
[Quickstart](../../README.md#quickstart) · [DeepSeek guide](../../demo/deepseek-context/README.md).

## Capture and Query Your Own Agent

With a supported agent installed and authenticated:

```sh
./agentprov launch --file-diff -- dsh headless --json 'Inspect the project and run its tests.'
./agentprov launch --context-dir /path/to/sessions -- codex
./agentprov context coverage --run RUN_ID
./agentprov context list --run RUN_ID --kind configuration --revisions
```

| Source | Context integration |
| --- | --- |
| Claude Code | Hooks and native messages/tools, permission-mode changes and auxiliary session state |
| Codex | Native rollout messages/tools, completed-message events, resumed thread settings and world-state snapshots |
| DeepSeek Harness 0.1.7-rc.2 | Native `session.v4.jsonl.zstd` and supported v3 transcripts |
| Kimi / Grok | Existing supported transcript formats |

Claude Code 2.1.293 and Codex 0.159.2 were exercised with real development tasks,
same-session continuation and signed export/import. The [compatibility table](../agent-context.md#native-format-compatibility)
separates these checked source formats from kernel and TLS coverage.

Context discovery and parsing run after execution exits. Explicit directories,
files and session IDs are supported. Resume boundaries and source identities
preserve the distinction between earlier history and current activity;
ambiguous source selection is reported separately.

The [context guide](../agent-context.md) covers capture options and CLI queries.
The [HTTP API](../agent-context-api.yaml) exposes paged entries, saved content,
configuration comparison, coverage and recorded links.

## Evidence and Capture

Large bodies are redacted before hashing and stored in bounded chunks that travel
with the forensic bundle. Saved content is read from evidence storage, independently
of the current workspace. Final changed-file text is opt-in and represents the
state at capture.

Context and runtime coverage have separate reports. Source-provided permissions,
configured approval policies and actual approval records retain their individual
meaning. Direct records and inferred associations remain distinguishable, with
their evidence references and confidence. Signature and graph checks establish
evidence integrity; coverage reports describe what was collected.

Native capture improvements preserve process-lifetime identity, kernel capture
timestamps and process-scoped attribution across cgroup migration. Bounded
shutdown draining and durable pending batches preserve late-attribution evidence.
New exports include stored telemetry batch membership for offline integrity checks.

## Upgrade and Compatibility

- Back up the data directory before upgrading. Existing stores migrate to schema
  19; older binaries are not a supported downgrade path for an upgraded store.
- Six historical signed demo bundles, attestations and public keys remain
  unchanged. New context fields in historical records remain absent.
- Linux amd64/arm64 kernel capture requires the appropriate kernel, cgroup and
  BPF/perf access. macOS provides replay and application recording. See the
  [deployment guide](../amd64-kvm-k3s.md) for per-probe and TLS support.
- `launch` signing remains opt-in with `--sign-key`; `--file-diff` selects
  workspace comparison and saved final changed-file text.
- LLM/Jev evaluators remain optional examples outside the capture path.
