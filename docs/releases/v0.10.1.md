# v0.10.1: Safer execution and clearer evidence

English | [中文](../zh-CN/releases/v0.10.1.md)

Release notes draft. This version has not been published.

v0.10.1 focuses on daemon access, recording compatibility, correlation accuracy
and TLS capture reliability. The Dashboard retains its existing layout and
investigation controls.

## Before upgrading

Read the [upgrade guide](../upgrading-v0.10.1.md). Several defaults change:

- The daemon requires a bearer token, reuses its local token file and validates
  browser requests. Body-bearing writes require JSON.
- HTTP recording has a 60-second default timeout, a restricted working directory
  and a minimal child environment. Shell wrappers require an explicit option.
  Local `launch` and `record` retain interactive input and long-running workflows.
- Bundle import verifies the signature with `--pub-key` before writing evidence.
  Historical unsigned imports require the explicit `--allow-unverified` option.
- Docker-backed compatibility commands drop capabilities and use the caller's
  effective UID:GID by default, with an explicit task-user override.

Back up the data directory before upgrading. Existing signed demo bundles and
their keys remain usable.

## Correlation and investigation

Intent coverage now follows individual tool calls. One call's intent record no
longer hides another call's missing context. Delegation analysis keeps ambiguous
messages as candidates, while explicit call bindings and persistent policies
retain their distinct scopes.

Outbound evidence separates three questions: which content appeared in the
payload, which reads could have supplied it, and which execution produced the
record. Exact paths, available content versions, observation times and explicit
identities support the association. The detail reader preserves these distinctions
with source references; signed bundles and selected replays retain the same states.

## TLS capture

Capture gaps, missing chunks and protocol-state loss are retained as incomplete
fragments. HTTP/1.1 reconstruction and HTTP/2 HPACK decoding stop using damaged
state. Incomplete content stays available for inspection without generating
model decisions or request/response pairs from partial bytes.

Native capture records call sequence and chunk offsets, and combines contiguous
fragments from one call. Process and library hints now trigger bounded, targeted
TLS discovery; attached library targets can be reused by later short-lived
processes. Explicit library configuration remains useful for the earliest calls.

On amd64, function metadata also supports stripped Go binaries and PIE.
BoringSSL libraries and static programs with resolvable function symbols can
be configured with `--tls-target`; installed host OpenSSL libraries attach
before readiness.

The ordinary per-call capture budget remains 4 KiB. The existing Dashboard
reader shows message integrity, fragment reasons and capture positions separately
from display pagination, including in offline replay.

## Native capture lifecycle

The reader uses a bounded queue and a configurable kernel ring buffer. The
default ring is 64 MiB; `--ring-buffer-mib` selects a power of two from 1 to 256.
On shutdown, syscall and TLS probes detach before buffered records are drained.
This preserves pending evidence while allowing capture to stop on busy nodes.
Current and historical ELF diagnostics retain their Chinese translations.
The [shutdown regression report](../benchmarks/v0.10.1-shutdown/README.md)
records the before/after tests and ARM64 acceptance.

## Compatibility fixes

Local terminal input and Ctrl-C retain the foreground process group. Bounded
daemon jobs keep timeout and descendant cleanup. Independent CLI command trees
use their own data directory and language settings.

Artifact export accepts valid names while retaining destination checks and
restricted file permissions. Signed import scripts and daemon examples now
follow the current verification and authentication defaults.
Quoted commands now receive the same redaction in table fields and JSON objects,
keeping record manifests consistent after signed export and import.

## Linux x86_64 validation

The x86 sensor now reads named tracepoint syscall numbers without including
alignment padding. Probe generation selects BPF ISA v3 for TLS atomic counters.
Native syscall/TLS, guest service, K3s attribution, Pod recreation and recovery
checks passed on Ubuntu 6.8. The [acceptance report](../benchmarks/v0.10.1-x86/README.md)
records the tested source and artifacts. A [follow-up report](../benchmarks/v0.10.1-procfs/README.md)
covers namespace-aware procfs lookup on WSL and nested containers, including
access-state sampling and TLS discovery. Original kernel process identities
remain intact; mapping gaps appear in capability reports. After the Windows host
update, [real KVM acceptance](../benchmarks/v0.10.1-kvm-postreboot/README.md) also
passed native capture, TLS, K3s, signed replay, recovery and service restart.
The WHPX guest crash was traced to inconsistent CET and state-save CPU features.
Selecting `-cpu max` fixes that configuration while keeping shadow stacks enabled;
the [CET follow-up](../benchmarks/v0.10.1-whpx-cet/README.md) records the checks.
Guest acceptance now rejects that inconsistent CPU feature combination early.
