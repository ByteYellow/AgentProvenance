日期：2026-10-17。基于 `cd66fa9` 的六处审查问题完成修复，并复跑已有验收流程。机器可读结果见 [acceptance.json](acceptance.json)。

## 修复内容

| 问题 | 修复后的行为 |
| --- | --- |
| 采集与查询争用数据库 | 已升级的库打开时不再写迁移信息；原生缓冲按最多 16 行、约 50 毫秒分段提交，短暂写锁争用最多尝试三次。定时封存独立于入库，队列每批重新排序；取消处理后立即恢复可重试状态。 |
| 损坏日志覆盖上次分析 | 替换图谱前校验全部输入；JSON 或助手内容损坏时报告行号，保留已有对象和关系。 |
| Dashboard 显示旧校验结果 | 概览检查当前数据库和对象内容；修改关系、损坏对象文件或数据库查询失败都会反映在结果中。旧证据包状态不再替代检查。超过 5,000 个对象仍使用完整校验入口。 |
| 未知置信值显示为零 | 未知的运行环境来源保持空值，显式零值继续保留。 |
| 旧版 Demo 视图变化 | 保留历史进程节点和线程组的展示规则；新版本进程生命周期语义继续有效。 |
| WSL OpenSSL 测试误认 PID | 从测试程序的实际启动事件获取内核 PID，支持不同 PID 命名空间。 |

分段提交的回归覆盖“前段提交、后段失败、重启恢复”，检查事件、行回执、清单和累计计数保持一致。持续采集测试直接等待自动封存和入库；停止后恢复测试检查没有延迟重试或重复事件。

## 环境与复现

Windows 侧 QEMU 使用 **WHPX 硬件加速**，运行 Ubuntu 24.04.5 / K3s v1.36.4+k3s1 的临时快照。来宾识别结果为 `qemu`。本机 WSL 当前没有暴露 KVM 所需的虚拟化扩展，硬件 KVM 加速这一层待环境恢复后补跑。TCG 软件模拟在这台机器上出现超时和内核丢事件，因此最终虚拟机结果采用 WHPX。原来的镜像未改动。

使用原有脚本和默认等待时间：

- [常驻服务验收](../../../scripts/accept_kvm_guest.py)
- [K3s 验收](../../../scripts/accept_k3s_guest.py)
- [原生采集验收](../../../scripts/accept_sensor_live.py)，参数包含 `--require-cgroup-lifecycle --pause-drain 1.5`
- [旧版 Demo 验收](../../../scripts/accept_legacy_context.py)与[DeepSeek 验收](../../../scripts/accept_deepseek_context.py)

此次只验收 x86；ARM64 沿用已有验收。本轮没有执行此前暂缓的 24 小时持续负载测试。
