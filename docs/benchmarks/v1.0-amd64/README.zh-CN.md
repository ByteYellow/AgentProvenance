## 本轮修复

- 恢复原请求时，按已验签并持久保存的交付清单读取对应检查点。执行端后续
  产生的新检查点与原来的不可变证据包分别处理。回归覆盖普通重放、ACK 请求
  丢失、ACK 响应丢失和执行器重启，并核对命令副作用只发生一次。
- 内核事件时间通过有界的单调时钟与系统时间配对采样转换。注入 8 毫秒调度
  延迟时，旧实现的回归失败，新实现通过；相邻访问控制用例沿用原时间容差通过。
- 派发前检查调用方、目标代次、接收方、密钥、工作进程和采集就绪状态。
  `wait_capture` 可以显式配置，提前交付会有提示。可选的本地 runsc / Firecracker
  检查只检查依赖和权限，不启动任务。
- guest 镜像补齐 udev，并确保网络和服务配置可读。回收时核对控制端保存的
  目标代次、预期执行清单及全部回执；空清单或身份不匹配时保留证据盘。

## 性能预算

基线与候选使用同一台 4 vCPU KVM、Go 1.26.4、Linux amd64、关闭 CGO、
`-trimpath` 和 `-s -w`。测量期间保持节点服务状态一致，完成后恢复服务。
预算在候选测量前冻结。Sensor 与遥测使用 v0.10.1 基线；Browser/Notebook
属于本版新增入口，因此使用干净的 v1.0 源码构建作为成本基线。

| 固定工作负载 | 结果 |
| --- | --- |
| Sensor off/minimal/default，突发与限速负载，各三轮 | 18 项预算全部通过 |
| 十万事件摄入和查询，三次基线测量 | 5 项预算全部通过；候选处理耗时 55.84 秒、RSS 峰值 82.1 MiB、查询 p95 为 11.15 毫秒 |
| Browser/Notebook basic、detailed、排除附件，各三轮 | 68 项预算全部通过 |
| 1 MiB 缓冲区过载 | 如实报告丢失；默认缓冲区的突发与限速负载均未报告内核丢失 |

工作负载、计时余量和存储口径见[性能验收说明](../../zh-CN/performance-validation.md)。
`report.json` 保存预算摘要及逐项比较结果。

最终候选包继续使用原预算复核，Sensor 18 项和上下文成本 68 项全部通过。
遥测首轮处理耗时为 **75.89 秒**，超过 **69.19 秒**预算，其余四项指标通过。
这次超限完整保存在 `release_performance.telemetry` 中。

随后在每次测量前完成待写数据落盘，按“基线、候选、候选、基线”的顺序交叉复测。
候选耗时为 **54.80 秒、55.51 秒**，基线为 **56.13 秒、69.05 秒**，四次均符合原预算。
首轮超限时未记录足够的数据来确定具体原因；交叉复测未出现持续的候选版回归。
四次对照与首轮超限一起保留，预算没有调高。

## 候选包

`agentprov_v1.0.0-candidate_linux_amd64.tar.gz` 及 SHA-256 校验文件已保存在
维护者交接目录。结果索引记录压缩包完整哈希、构建信息、guest rootfs 和运行时输入摘要。

状态均按原语义保留。已有 DeepSeek 实录的签名、正文、查询和重复导入检查也已通过。
全量 Go 测试、vet、受影响包的 race 测试、Python、八组前端测试和中文文档检查通过。

阅读界面另存为 `AgentProvenance-v1.0-reader-preview-20261116.zip`，解压后打开
`index.html` 即可。四份示例的文件清单均已核对，也可以按下方说明从源码重建。

## 复现与审核

[执行交接指南](../../zh-CN/execution-handoff.md)运行。Firecracker 的实际启动

rootfs 和新的输出目录。失败时保留测试磁盘。

Notebook 合成样例。按维护者的决定，先保留供后续集中审核，正式 Dashboard 布局保持原样。

原始采集记录、签名私钥、模型凭据、数据库和完整诊断日志留在私有验收目录。
此目录只保存审阅后的摘要与证据哈希。合并 main、打 tag、发布和 Pages 上线
留待最终发布审核。
